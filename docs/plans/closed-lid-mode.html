Closed-lid mode for Desklamp

Project: Desklamp 2026-10-14 Reviewed plan, awaiting go

Plan: ship this in three steps, each of which can stop the work before it costs much.

  1. Notarize Desklamp (v1.1). Sign it with your Developer ID and get it notarized by Apple. That removes the "Open Anyway" step for every new user, and it ships on its own. About half a day, plus one keychain command you run yourself.
  2. Spike (one throwaway day). Prove that a sandboxed, signed Desklamp can install a root helper and talk to it. Also prove that the Mac really does sleep when protection is withdrawn with the lid already closed. If either fails, you get a decision, not a workaround.
  3. Closed-lid mode (v1.2). An opt-in menu checkbox, plugged in only. A root helper holds the setting under a 30-second heartbeat. Any safety stop holds until you turn the mode back on. Several days, plus a review.

What the review changed: it found that the 4-hour and battery limits would have quietly re-armed 10 seconds after firing. It also caught the missing helper-update path and a source build that would have broken. All three are fixed below.

Your calls

  1. Plugged-in only for v1? Recommended: yes. Closed-lid mode turns off the moment you unplug, so a Mac never runs closed in a bag on battery. Battery support with a charge floor can come later if people ask.
  2. If the spike shows the sandbox blocks the helper, drop the sandbox? Recommended: decide after the spike. Dropping it changes the "No permissions" and "sandboxed" promises (README lines 21 and 52, npm README line 26) for every user, not only those who turn the mode on.
  3. 4-hour hard cap on closed-lid, even with "Indefinitely"? Recommended: yes. When it fires, only the lid behavior goes back to normal. The Mac still stays awake while the lid is open.
  4. Menu wording. Strawman: a checkbox labeled "Keep Awake with Lid Closed" under Allow Display Sleep. When a safety stop fires, one gray line under it says why, for example "Lid mode stopped: unplugged".

Steps

Phase A: Notarize (v1.1)

  1. Check the account first. You run xcrun notarytool store-credentials desklamp-notary once. Then a throwaway submit proves the certificate and its key work, and that the account's agreements are signed.
  2. Sign only in scripts/package.sh. The Developer ID identity, team and hardened runtime are passed as build overrides there. project.yml stays ad-hoc, so the public "Build from source" path still works for anyone without an account.
  3. Fix the packaging order. Notarize and staple the app first. Then build the zip and DMG from the stapled app, notarize and staple the DMG, and write SHA256SUMS last. The ad-hoc re-sign at package.sh:28-31 becomes a Developer ID re-sign: helper first, then the app, never --deep.
  4. Update the copy. Drop the Open Anyway step and GIF (README.md:13-15) and the ad-hoc wording (README.md:48, npm/README.md:22).

Phase B0: Spike (throwaway branch)

  • Helper round-trip. A signed, sandboxed build registers a trivial root helper and makes one call to it on macOS 14 and on this Mac's OS. If the direct connection fails, the next try is the route Apple recommends: move the connection into a small XPC service inside the app bundle, so the sandbox exception stays out of the main app. Dropping the sandbox is the last resort.
  • Sleep after withdrawal. With the lid closed, clearing the setting must actually put the Mac to sleep: pmset -g log should show a clamshell sleep. If it doesn't, the helper also has to force sleep itself when the lid is shut.

Phase B: Closed-lid mode (v1.2)

  • Helper target. A root daemon is embedded in the app and registered through SMAppService, only the first time the user turns the mode on. Each side checks the other's code signature before talking.
  • Lease, keyed per connection. The app renews every 10 seconds and the lease expires after 30. The timer uses uptime, not the wall clock. When the app quits or crashes, the dropped connection releases the lease immediately.
  • Safety stops latch. The 4-hour cap, unplugging, unknown power and a serious thermal state all hold until the user turns the mode back on. Later renewals are refused.
  • Recovery. The original setting is saved to a root-only file on disk before anything changes. It gets restored on release, on stop, when the helper starts, and when the helper is shut down. A failed restore keeps retrying.
  • Read the real setting. It comes from the power-management registry (IOPMrootDomain), not from parsing pmset, which leaves the line out on a clean Mac. A missing value fails safe.
  • Updates. The helper reports its version. When the bundled helper is newer, the app releases the lease, confirms sleep is back on, then re-registers the helper with retry. install.sh and the npm installer release the lease before swapping the app bundle.
  • App side. A new ClosedLidController owns the connection and the heartbeat. The approval status is re-checked every time the menu opens and whenever the app becomes active. The checkbox is hidden on builds with no team signature.
  • Tests. Lease unit tests: expiry, the cap, a renew after a stop is refused, unplug, two clients, restore from the saved file, and a failed restore that retries. A manual gate on your Mac with the lid closed: kill the app, the cap with a shortened debug timer, and unplug. Each must end in a real clamshell sleep within about 40 seconds.

Out of scope for v1
  • Battery operation. Covered by decision 1.
  • A "Remove Helper" button. Turning the setting off is enough, because the helper holds nothing without a lease.
  • Settings UI for the caps. v1 uses fixed defaults.
  • Sparkle auto-updates and licensing. Desklamp stays free, which is the edge over WakeBee.
